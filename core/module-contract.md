# 模块契约


每个规则模块使用七个 YAML 字段：`id / layer / priority / depends_on / conflicts_with / load_when / not_for`。id 在全库唯一，依赖和冲突以 id 引用，不使用显示标题。layer 为所在分层目录；旧 references 按职责赋层，不移动旧路径。priority 只管加载先后，不能推翻主技能既有 P0/P1/P2 质检。

```yaml
id: color-system
layer: visual
priority: P0
depends_on: []
conflicts_with: []
load_when: ["用户指定配色或需要色彩叙事"]
not_for: ["只检查兵器接触"]
```

depends_on 仅列完成本模块不可缺的规则，交叉链接不是强依赖。已有用户授权限制必须传递；批准一个模块不批准它链接的其他高级模块。命中 not_for 跳过；若显式依赖反而不可用，先缩小任务、提供候选或分阶段，不能悬空执行依赖模块。发现依赖环停止该分支并修配置，不无限递归。

控制层能力未核实不能填肯定值；生成层只写可见/可原生生成信息；分析、评分、软件操作进入管理层。所有新模块均服从[模板契约](../references/template-contract.md)和[默认交付协议](../references/anti-lazy-and-delivery.md)。模板与风格卡用于诊断补缺，不用于替换用户的表达。

## 无依赖解析器的头部写法

为保证标准库检查器可直接运行，本仓库采用YAML的平坦子集：字符串标量、单行字符串数组；数组推荐JSON兼容写法，如`["dialogue-engine"]`，空值用`[]`。不使用嵌套映射、多行块或YAML锚点。主SKILL的name/description使用宿主技能元数据规范，不加模块七字段替换它。

## 情境细节的静默推演与负荷边界

当创意、场景与人物状态已定或获准代拟时，生活微动作、道具纹理、环境反应、既定接触反馈、当前主观镜语与声音意图属于默认基础情境处理，不另问加载授权，不输出词库、模块说明或“我自动加了什么”。扫描不是强制填满：依现场刺激、已有物件/材料、身体条件与当前信息，只选有效细节；没有依据就不加。

### 不增加核心必执行的三种情况
1. 固定外观/材质/既有磨损、持续风向/主光等静态条件不是新动作。
2. 既定接触、落脚、握持的直接可见结果，可在原因果链内细化，不能借此改胜负或支撑逻辑。
3. 可删而不改变剧情、主动作、接缝和验收的非关键表演/粒子，放现有氛围位，所有模块总共仍最多2条氛围，不额外加一套额度。

新取物、摔倒、失明、断武器、破墙、换接触对象、影响选择的呼吸中断等若是独立事件，不能被标成免费氛围。默认不加这个候选；用户所求确实包含它时依原3+2及导演因果链规则计数/拆分。不得把一个字段叫“丰富细节”后藏多次动作。此条落实[原模板契约](../references/template-contract.md)，不改其必执行/氛围/禁止上限。

### 授权与状态
默认基础细节不自动授权更改人物身份、关键伤势、核心道具功能、剧情/结局，也不打开深度台词、心理卡或真实武学检索。原创意就绪确认与批准资产继续优先；用户说保持静止、不要小动作或极简时相应不加。未知角色状态不得为了描写而定案心虚/前史。
生活动作与道具表演按同一场次共享“一个角色一个新增小动作”，已选信号在内部短摘要续接，不因换G/GEN重置。新模块均不依赖对方全读；单轮新增内容文件仍≤6，优先已有摘要，不把全部新模块一起挂载。

### 三层与最终产物
仅可见画面、适用且本次已核原生声音进生成层，真实平台控件进控制层；精确顿帧、变速、滤波混音与合成进管理层。默认自足白话，不附额外说明或双版图纸；“静默”不包括偷偷改用户核心目标或伪称能力已核。最终转写继续执行[防偷懒交付](../references/anti-lazy-and-delivery.md)。
