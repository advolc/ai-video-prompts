# Rule ownership

The authority ladder remains in SKILL.md. This map assigns maintenance responsibility, not another priority system. [owners.json](../assets/owners.json) is the machine-readable registry of each rule's source heading. Other modules apply the rule or supply examples; they do not establish competing defaults, numeric thresholds or exceptions.

Psychology explains why and what someone does to another; body vocabulary realizes posture/distance; facial display realizes audience-dependent masking; depiction grammar writes these choices for the camera. Keep these distinct craft responsibilities. Their overlap is useful when it translates between layers; repeated policy text is not.

When changing a rule, edit its owner first, inspect incoming references and examples, then run structural and behavioral regressions. A valid owner link cannot prove the absence of semantic contradiction. If runtime wording conflicts, follow the main authority ladder and the topic owner; flag the stale application for maintenance.

## Owner registry

The exact topic-to-file-and-heading mapping lives only in [owners.json](../assets/owners.json). Update that registry when an owner moves. The structural checker verifies each entry resolves; there is no second hand-maintained ownership table here.
