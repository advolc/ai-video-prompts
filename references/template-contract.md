# 提示词模板的结构契约

用于创建、填写或改造复用模板；实际平台使用确认仍执行[生成交接检查](generation-handoff.md)。完整剧本转写、Lite Mode、长因果链与三项交付话术统一执行[全局协议](anti-lazy-and-delivery.md)。空壳见[生成输入模板](../assets/templates/生成输入模板.md)，后期文件用[制作备注模板](../assets/templates/制作备注模板.md)，已填项目见[萧烬压境示例](../examples/萧烬压境_填写示例.md)。

## 四条结构规则

1. **分层。** 生成层只写可见角色/场景、动作、文字运镜、接触反馈及当前模式可原生生成的声音；控制层承载真实界面参数与资产绑定；管理层放独立制作备注。生成输入文件的管理部分只留制作备注链接，不展开剪辑或QA内容。
2. **限事件。** 本模板中每个约5秒事件单元最多3条必执行、2条氛围、2条针对性禁止；不用的行删除，不强制凑满。超过则拆单元，不把多次攻击合并为一条“必执行”来规避。数字是用户选择的设计规范，不是模型能力测试结论。
3. **留空位。** 模板壳只留字段名、填写提示及`______`，不含项目已填值；示例、原稿和制作备注另存。正文不得用引用块夹入具体角色值，避免复制时把示例当设定。
4. **挂退路。** 每个固定项和能力假设都在平台适配表有对应行，写明原生支持时如何用、缺失时怎么办，以及是否改变关键设定。已批准的身份、构件数量/空间结构、关键动作和结局不能自动删改；降级只给候选，改变这些项须先取得用户选择。具体项目的六瓣等形态只保留在该项目示例，不成为其他术法的默认值。

## 生成、控制、管理怎样分开

| 内容 | 放置位置 |
|---|---|
| 角色可见特征、花瓣数量与空间关系、场景锚点、摄影侧/景别/拉远等描述 | 生成层固定项或事件段。固定项写结构，事件段写本次变化；数量少并不证明动作简单 |
| 真实界面提供的参考绑定、首帧/尾帧文件、时长、分辨率、种子、运镜预设 | 控制栏。无对应控件就不编参数；文本运镜不能为省“必执行”额度而伪装成运镜参数 |
| 六项接缝状态的可见描述 | 第三部分生成承接状态，只将本段需要的左右、朝向、动量、手位、术法与损毁写给模型 |
| 取哪张尾帧、剪几帧、段间对应表、选帧理由、失败标签、验收与授权记录 | 独立制作备注；批准图文件绑定仍在控制栏 |
| 已确认当前模式支持的环境音、撞击音、术法音、短台词 | 生成层对应事件的时间提示内；是期望事件顺序，不保证帧级同步。台词必须有实际文本和说话者 |
| 后期配音台词、音色调整、混音、BGM精细编排、口型修整 | 制作备注。原生声音不可用时将原生音频行移到备注，保留设计，而非抹掉声音任务 |
| 后期速度、定格、接触后的白闪与震屏、导出和QA | 制作备注。若用户明确选择原生生成某个可见闪光，写成具体画面变化；不要把后期操作指令混入 |

参考绑定在控制栏唯一维护。模板里的`@Image`只在真实接口确有该绑定方式时使用；无图则删掉，改为文字描述且不称“文字锁定成功”。若平台明确要求正文使用媒体引用标记，控制栏保留绑定源，生成层只插该平台所需标记；这是经过确认的语法例外，不是重复粘贴整张绑定表。

## 事件上限与主要交互检查同时生效

“最多3条必执行”不等于“一段可稳定完成三次攻防”。每条必执行是一个可观察条件；可描述同一次反击的触发、展开和结果。主交互仍按生成交接检查判断。拍瓦、开花、雷击推开虽可写成三条，仍同时包含地面接触、构件展开和敌人受推，是高风险候选；必要时再拆，不把3+2当成功保证。

术法数量、主体身份和因果所需的可读构图不能降为氛围。衣发、粉尘可为氛围；若其承担唯一受力证据，就改为必执行或另设清楚的位移结果。单元约5秒允许按动作调整，不强制把1秒接触拉成5秒顶拳。G编号是模板事件单元，GEN是实际请求，二者可不同；拆事件单元不等于已获准改为多次生成。一次15秒包含多个单元时仍核查整次请求的负荷。

文学剧本即使已按秒切分，也先检查并转译到本模板，禁止把原段照搬为必执行。先按全局协议的导演豁免判断同一击因果链，再决定是否拆独立交互；同一5秒内多个连续动词可合并为一条必执行，并在备注说明连续依据。约10秒低接触因果链也可保留长单元，工程字段仍不超过3+2，不按动词数切碎。Lite Mode可以只给精炼自然语言，内部仍完成必要负荷与因果检查。

动作、台词与表演心理的辅助模块属于用户授权后的设计检索工具，不改变主模板字段与3+2限制。提炼结果按本契约填生成层或转制作备注，不添加导出字段、不破坏脚本解析；身体反应进入必执行/氛围，取景描述才进入单元摄影。可选入口：[动作参考卡系统](action-reference-system.md)、[台词深度引擎](dialogue-engine.md)、[表演与心理动作系统](performance-and-psychology.md)；最终交付默认只给纯文本，工程结构仅在用户主动明确索要时展示；统一遵循[主入口交付规则](../SKILL.md#交付与完成条件)，不以工程结构代替可复制正文。

## 平台适配的边界

- 单段时长不足：按实际可选时长规划多段请求和剪辑净长；只有确认单段5秒且用户接受分段时，30秒才候选为6×5秒，余量与去重另算。
- 无角色参考：采用可区分的发型、五官、服装和可见表情姿态；严格身份一致性仍待输出验证。
- 无尾帧：可用首帧时只填首帧；下一段若可接图再选合格输出图。不能用“后期选帧”冒充控制了上一段结尾。无首尾帧则文字承接并检查实际输出。
- 复杂空间关系执行差：先给结构参考、稳定构图或另做术法镜头；若必须简化错层，记录改动并确认，不自动牺牲术法固定设定。
- 无原生音频或能力未核：生成稿不放原生声音行，声音设计留制作备注。已确认支持时再将选定声音放回对应时间段；无需删除整套声音方案。

## 文件与导出

项目文件包括生成输入稿和独立制作备注；角色填充值只出现在项目示例/项目稿。原始《萧烬压境》完整文本单独[存档](../examples/萧烬压境_原稿存档.md)，不作为新版模板或直接输入。

工程文件用FIXED、EVENT和SEAM注释标记可导出范围，控制栏、适配表、原设计意境句及交付说明置于其外。模板用于后台组织与质检，最终默认只交自足的白话纯文本。仅当用户主动明确索要工程图纸/分镜表而实际展示工程结构时，才附全局协议的三项说明；不要求用户先看工程表或再次申请转写。可用[scripts/export_prompt.py](../scripts/export_prompt.py)选择一个事件导出纯文本底稿，默认移除工程标签并按起点、动作、摄影效果、终点拼接；`--format structured`才保留工程摘录。默认输出到标准输出，也可指定新文件；导出拒绝未填空位及超出3+2/禁止上限的结构。示例：

```text
python -X utf8 ai-video-prompts/scripts/export_prompt.py ai-video-prompts/examples/萧烬压境_填写示例.md --event G10 --output work/G10.txt
```

导出器只证明选择范围、去标签与字段结构，不会理解一行里藏了几次攻击，也不会核实平台支持、动作物理或视频质量；连贯白话与含混代称仍需AI语义润色。固定前缀在编写时填一次，但平台没有项目记忆时，每次请求仍带本段必要固定内容。用户只要一条提示词时可直接交纯文本，分层与负荷检查仍在内部执行，不强制发送完整模板；模板较长时按全局协议给Token Saver提示。

命令从包含技能文件夹的项目目录运行，先创建项目work；安装在别处时改用绝对输入路径。不能让新手在技能源码目录建立运行历史，完整使用方式见[README](../README.md)。

提供脚本入口时附“纯文本底稿→保持事实清单的电影感润色”说明，措辞见全局协议，不把机械拼句当作已优化的平台最终稿。

## 新模块接入模板

视觉签名、可见构图/光线、动作与经过可见化的表演进入生成层；平台支持且本次使用的图像绑定、首尾帧、时长/尺寸/种子进入控制层；叙事分析、台词深度卡、剪辑、调色合成、混音、评分和版本交接进入独立管理层。新模块不新增导出标记、不改主模板字段，仍是原FIXED/EVENT/SEAM契约。

固定视觉描述不占动作事件条数；真正新增的身体反应或环境变化必须计入原3+2，不得称为辅助模块就额外加3条。默认经语义转写交自足白话，仅用户明确要图纸时展示字段。脚本解析逻辑不改；新的分析卡不能直接送入导出器。接入管理见[模块契约](../core/module-contract.md)。
